
My pipeline takes in three or four arguments (input, which is the input file, output, which is the output file, config, which is the config file, and verbose, although this argument is optional), and cleans and validates the provided data. Data moves through this pipeline first through input as file, which is then validated and loaded in. Then, the data is validated to make sure there are not missing columns or values, then it is processed, saved as a csv, and returned, along with a cleaning report. Within the pipeline there is .gitignore, the README file, the main pipeline, requirements for my venv, src/ (which holds the required functions), config/ (which holds the config file), fixtures/ (which holds the sample data), and output/ (which holds the output). For data_loaders the main responsibilty is to take in the filepath and load in the file depending on the suffix type, for data_output the main responsibility is to save the new dataframe as a csv, which is also the output. Data_processor cleans the data by removing duplicates, handling missing values, removing outliers using either iqr or z-score, processing data based on the config file, or creating a cleaning report. Similarly, data_validator validates the dataframe and returns the data, as long as the required columns exist and the numeric columns are valid, and utils holds functions to organize the program such as setup_logging and validate_input. Finally, the init module acts as a package that holds the required functions to be imported to main file, which is the pipeline file, and is used for implementation. 



Example command: python3 pipeline.py --input fixtures/sample_data.csv --output output/clean.csv --config config/config.yaml
